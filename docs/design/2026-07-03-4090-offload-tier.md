# 4090 Offload Tier - fail-open GPU services for second-brain

- **Date**: 2026-07-03
- **Status**: DRAFT (for review, not yet approved to build)
- **Owner**: Scott Idler
- **Origin**: Project shape agreed in the 2026-07-02 second-brain session; captured in `obsidian/notes/2026-07-02-4090-offload-tier.md`. This doc formalizes it. Primary driver: keep confidential meeting audio off Groq.

## Problem

Desk is a 2012 Sandy Bridge-EP: AVX only, no AVX2/FMA (see `reference-desk-cpu-no-avx2`). All local ML is off the table there, so today everything rides Groq / Anthropic APIs. Two costs follow:

1. **Privacy**: `bin/meeting` ships colleagues' voices to Groq for transcription. As meeting ingestion (unlock #3) gets real use, that stops being theoretical.
2. **Dead capability**: the cross-encoder rerank stage is built and evaled but cannot run on desk, and high-volume low-stakes LLM calls (tagging, classify, slide-vision) burn API budget.

There is a spare asset: a Windows gaming box with an RTX 4090 (24GB VRAM) on the LAN.

## Goal

Turn the 4090 box into an **opportunistic LAN accelerator** exposing OpenAI-compatible HTTP endpoints (whisper + LLM), that second-brain consumers use when available and transparently fall back to the current path (Groq / Anthropic / CPU) when it is off, asleep, or gaming.

## Design rules (non-negotiable)

- **The 4090 is an accelerator, NEVER a dependency.** Every consumer probes the endpoint and falls back on miss. Same fail-open pattern as oracle's rerank warmup probe. Nothing in the pipeline may block on the box being up.
- **Windows stays a dumb appliance**: WSL2 + Docker + CUDA, two OpenAI-compatible containers, never a machine to SSH into after setup. Reach via LAN hostname or Tailscale (so lappy gets it too). Optional wake-on-LAN before fallback.
- **Network tax is a red herring**: 1 hr of 16kHz mono meeting audio is ~120MB (~1s on gigabit); rerank/LLM payloads are KB-scale JSON. The real costs are availability + VRAM contention with gaming (ollama's idle model-unload, default ~5 min, handles that).
- **OpenAI-compatible endpoints** so fabric, scripts, and the ecosystem point at a custom base URL with no code changes.

## Workloads, ranked by value

1. **Confidential meeting transcription (the killer use case).** faster-whisper server (OpenAI-compatible) on the 4090, ~20-40x realtime for large-v3, keeps colleagues' voices on-LAN. Seams already exist: borg config `transcriber.url` (currently pointing at nothing on `:8090`), and `bin/dictate` + `bin/meeting` get a try-LAN-first-then-Groq fallback (a few lines each).
2. **Unblock rerank.** Cross-encoder is built + evaled but dead on desk. Served remotely it is a ~10-20ms call, inside the latency budget. Needs a small Rust change: a remote rerank client in `vault::search` behind the same fail-open probe.
3. **High-volume low-stakes LLM calls**: tagging, classify, slide vision classification (Qwen2.5-VL class) via ollama / llama.cpp server. Keep Sonnet for distill/summarize where quality shows. Cuts API cost, closes another privacy surface.
4. **Embeddings: skip.** 2,400 notes on a 10-min incremental cadence is fine on CPU candle.

## Build shape

### Infra (Windows box, one-time)
- WSL2 + Docker + CUDA (mature in WSL2).
- Two containers: faster-whisper server + ollama (or llama.cpp server), both OpenAI-compatible.
- Expose on LAN; verify from desk with `curl`. Optionally join Tailscale.

### Rust / config changes (second-brain)
- **Fail-open probe helper**: a shared `probe(url) -> bool` with a short timeout, reused by every consumer (mirror the oracle rerank warmup probe; do not reinvent per call site).
- **`bin/dictate` / `bin/meeting`**: try `transcriber.url` first, fall back to Groq. Config carries the URL; absence or probe-miss = today's behavior.
- **borg**: point `transcriber.url` at the box; borg already has the slot.
- **`vault::search`**: remote rerank client behind the probe (this is the piece that resurrects the dead cross-encoder).
- **LLM routing**: route tagging/classify/vision to the local endpoint when up, else Anthropic; keep quality-sensitive calls on Sonnet regardless.

## Open questions (need Scott)
1. **Reachability**: LAN hostname only, or Tailscale too (lappy/travel)? Wake-on-LAN worth wiring, or accept "box is off = fallback"?
2. **Model choices**: faster-whisper `large-v3` (confirm), and which local LLM for the low-stakes tier (Qwen2.5 32B-class? Qwen2.5-VL for slide vision)?
3. **Config surface**: single `transcriber.url` + a new `llm.local-url` / `rerank.url`, or one `accelerator:` block in the relevant configs?
4. **Sequencing**: do the transcription seam first (highest value, smallest change), rerank second, LLM routing third? (Recommendation: yes, in that order.)

## Success criteria
- With the box up, a work meeting transcribes entirely on-LAN; with it down, `bin/meeting` falls back to Groq with no user action and no error.
- Rerank runs (non-null nDCG delta on an `sb oracle eval` run) when the box is up, and search is unaffected when it is down.
- No second-brain daemon ever stalls or errors because the 4090 box is unreachable.

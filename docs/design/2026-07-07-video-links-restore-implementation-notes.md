# Implementation Notes: Video Links Restore

## Phase 1: `description::extract_urls` + `merge_description_links`

### Design decisions
- `extract_urls` decomposes per-line rather than one description-wide regex pass -- `borg/src/description.rs:extract_urls` finds all URL occurrences on each line via `find_occurrences`, then derives labels per line via `line_links`, mirroring the shape-decomposition style already used by `github::extract_repo_slugs`/`slug_from_path` (helper functions composed, not one mega-regex).
- Markdown-link spans are found FIRST (`MARKDOWN_LINK_RE`) and their byte ranges recorded in `covered`, so the subsequent bare-token scan (`URL_TOKEN_RE`) skips them -- `borg/src/description.rs:find_occurrences`. This avoids double-counting a markdown-wrapped url as a second bare occurrence.
- The "sole url on line" check for label derivation counts BOTH markdown and bare occurrences together (`find_occurrences` returns one `Vec<UrlOccurrence>` per line, sorted by position) -- `borg/src/description.rs:line_links`. A line with a markdown link AND a second bare url therefore makes both bare, per the Data Model's "multiple urls on one line -> all bare" rule, read as applying uniformly regardless of markdown wrapping.
- The `www.` (scheme-less) alternative is included in `URL_TOKEN_RE` itself, not filtered out beforehand, so a scheme-less candidate is found, attempted through `Url::parse`, fails, and is counted+logged as a drop (`extract_urls`'s `dropped` counter and per-token `debug!`) -- rather than a token that is simply never considered. This matches the Data Model's "dropped-with-log, not silently lost" language literally.
- `trim_trailing_punctuation` (`borg/src/description.rs`) recomputes the open/close paren balance from the CURRENT token on every backward step, so a token like `.../Rust_(programming_language))` (theoretical double-wrap) trims exactly the unbalanced excess rather than all trailing `)` unconditionally.
- `name_url_label` uses `rfind(':')` (last colon before the url), not the first, so a `Name (owner): url` shape keeps the parenthesized qualifier as part of the label per the Data Model's "kept whole" instruction -- `borg/src/description.rs:name_url_label`.
- Dedup in both `extract_urls` and `merge_description_links` uses a plain `HashSet<String>` keyed on the exact url string (no `.to_ascii_lowercase()`), deliberately the opposite of `extract_repo_slugs`'s case-insensitive dedup, per the design's explicit finding 4.

### Deviations
- The Phase 1 success criterion (a) fixture ("the FILTERED description of `ht-4cbdf8`, returns all 10 URLs including the non-github `https://python.useinstructor.com/`") could not be sourced verbatim: the staged artifact at `~/.local/share/sb/borg/stages/ht-4cbdf8/` persists only `envelope.yml`, `body.txt` (the bare YouTube URL), and `distilled.yml` (`links: []`) -- the raw/filtered description text is not durably staged anywhere (per the design doc's own finding 6, the description is fetched a SECOND time inside `distill_for_publish_video` and not persisted as a separate artifact). Per the task's explicit fallback instruction, `test_extract_urls_ht_4cbdf8_representative_fixture` (`borg/src/description/tests.rs`) uses a CONSTRUCTED fixture instead: a numbered "10 down to 1" list built from the real staged `distilled.yml`'s `kind-specific.repos` (9 github repos: chonkie-ai/chonkie, VikParuchuri/marker, langfuse/langfuse, qdrant/qdrant, ollama/ollama, stanfordnlp/dspy, unclecode/crawl4ai, dottxt-ai/outlines, BerriAI/litellm) plus Instructor's actual non-github doc site `https://python.useinstructor.com/`, which is the concrete lost URL the design doc itself cites. This is disclosed here per the "same effect, correct seam" convention; the test comment also states the fixture is constructed, not verbatim.
- Same test also incidentally exercises the "Name: url" label rule for every line (via `N. Name: url` shape) -- not required by criterion (a) but left in as a bonus sanity check (asserted on first/last item only) since it strengthens the fixture without adding scope.

### Tradeoffs
- Decomposed per-line, imperative helper functions (`find_occurrences`/`strip_leading_marker`/`name_url_label`/`trim_trailing_punctuation`) vs. one large regex with named capture groups for the whole label-derivation rule. Chose decomposition: the label rule has multiple ordered cases with a "sole url on line" precondition that isn't expressible cleanly as a single regex, and the decomposed form matches the existing `github.rs` prior-art style this doc explicitly asks to mirror.
- `strip_leading_marker`'s "strip any leading non-alphanumeric run (emoji)" step is a general character-class strip rather than an explicit Unicode-emoji-property match. `regex`'s default (non-`unicode-perl`) build in this workspace doesn't necessarily carry Unicode property classes for every codepoint; a blanket "non-alphanumeric, non-quote" strip covers the documented "emoji/whitespace prefix stripped" case without depending on an emoji-specific character class, at the cost of also stripping a legitimate leading symbol in an unlikely edge case (not observed in the fixtures used here).

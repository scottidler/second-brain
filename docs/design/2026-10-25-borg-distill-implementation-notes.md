## Phase 1: PublishPolicy threaded through, no behavior change
### Design decisions
- `PublishPolicy { Vault, Scratch { root } }` is `pub` in `borg/src/pipeline.rs` (derive Debug, Clone, PartialEq, Eq) - public so every transport and integration test can name `pipeline::PublishPolicy::Vault`; being `pub` in a lib means the unread `Scratch` variant raises no dead_code warning.
- `policy: &PublishPolicy` sits right after `config` on `process_content`, `process_url`, `process_url_inner`, `process_youtube`, plus `process_text` / `process_text_inner` - the text handler redirects a URL-bearing text to `process_url`, so the policy must reach it or that path could not pass one.
- `process_youtube` names its parameter `_policy` with a comment: nothing reads it until the Scratch phases; `process_url_inner` only forwards it.
- Frames work dir is keyed by trace id: `try_extract_slides` (`borg/src/pipeline/handlers.rs`) gains `trace_id: &str` and the dir is `borg-youtube-frames/<trace_id>`; the `.mp4` inside keeps its `<video_id>.mp4` name.
- Whisper audio: `whisper_transcript` (`borg/src/youtube/engine.rs`) uses `tempfile::Builder` `borg-whisper-` TempDir per call, removed on drop, replacing the shared `$TMPDIR/obsidian-borg/`.
### Deviations
- `try_extract_slides` and `process_text`/`process_text_inner` also gained parameters; the doc names only four functions. Same effect, correct seam (the trace id has to reach the dir name; the text path has to reach `process_url`).
- The doc says "All seven production callers"; `process_content` has an extra `attachment_note` argument today, so the policy is inserted before `trace_id`, not appended.
### Tradeoffs
- Policy after `config` vs. appended last: after `config` keeps the "what to do with this run" arguments together and leaves `trace_id`/`attachment_note` trailing as they were.
- No new test: Phase 1 adds no behavior and no public function; the existing suite pins that the signatures change and nothing else moved.
### Open questions
- `cortex daemon::tests::test_duration_until_weekly_returns_valid_duration` fails on main on the Sunday evening before the US fall-back DST change (`Sun 22:00` is 7d+1h away in wall-clock time, over the test's `7 * 24h` bound). It is a clock-dependent test bug unrelated to this work; it self-clears once the Sunday 22:00 hour passes. Not touched here. Worth a fix (bound `7d + 1h`) whenever convenient.

## Phase 2: honor Scratch in the URL pipeline
### Design decisions
- The three policy-dependent decisions are methods on `PublishPolicy` (`borg/src/pipeline.rs`): `effective_config` (Cow: `Vault` borrows the live config, `Scratch` clones once with `staging.root = root/stages`, `enabled = true`, `layout = PerTrace`), `refusal` (non-URL under `Scratch`), `inflight_key` (`distill:<canonical>` under `Scratch`) - one place answers each question, each unit-tested.
- The non-URL refusal sits at the very top of `process_content`, before the trace lease and the permit wait, and closes the receipts row through `record_terminal_to_receipts` as `intake-rejected` (the same early-return shape as the lease-failure path), so the row never sits in `received` for the watchdog.
- `process_content` shadows `config` with the effective config right after the refusal, so Stage 0 and every later stage read it; nothing downstream needed its own override.
- `process_url_inner`: the ledger file is `Option` (`None` under `Scratch`), which skips both the lookup and the append with one value; the publish root (`publish_root`, replacing `vault_root_resolved`) is the scratch root under `Scratch`, used for `publish_slides`, `figures::store` and `UrlPublish.vault_root`; the note dest is `root`; `vault_dirs` is `[root]`; `obsidian_url` is `None` (the note is in no vault).
- `publish::publish_url_note` takes the policy through a new `UrlPublish.policy` field: under `Scratch` it writes the note with `atomic::publish_unique` and returns before the archive, the failure rkvr cleanup, and the orphan cleanup. `figures::store` takes the policy and skips its rkvr rollback under `Scratch`.
- The staging-persistence row is enforced by `scratch_staging_missing` (`borg/src/pipeline.rs`), called once in `process_url_inner` right after distillation: under `Scratch` a missing `root/stages/<trace>/distilled.yml` fails the run `publish-failed` before any note is written. The reason reads `staging persistence failed: <path> was not written`.
- `vault::paths::borg_distill_dir()` returns `~/.local/share/sb/borg/distill`, beside `borg_stages_dir()`/`borg_sources_dir()`; nothing calls it yet (the route in Phase 5 picks `root = borg_distill_dir()/<trace>`).
- `Config` and five sub-structs (`ServerConfig`, `VaultConfig`, `TranscriberConfig`, `GroqConfig`, `DaemonConfig`) gained `#[derive(Clone)]`, needed for the one effective-config clone.
### Deviations
- Staging persistence failure: the doc cites the article persist site (`stages/distill.rs:433-435`); I left all four distillers' log-and-continue persist sites (article, video, repo, thread) untouched and enforce "`succeeded` means `distilled.yml` exists" with one post-distill existence check in `process_url_inner`. Same effect for every URL kind, correct seam, and the ingest path cannot change.
- `distill_persist_failure_fails`: a literally unwritable `root/stages` (a file at that path, root-proof) fails at Stage 0 (`intake-rejected`) before the persist guard is reached, so that case alone would not bite on the guard. The test keeps it and adds a second case that obstructs only `distilled.yml` (a directory at its path): Stage 0 runs, the persist fails, and the run is `Failed` `publish-failed` with no note. Removing the guard fails the second case.
- `distill_policy_matches_ingest_note`: borg has no clock seam, so the clock is not pinned. The trace is pinned (both runs use one trace id) and the test masks the four wall-clock-derived values (`date:`, `ingested:`, `trace-expires:`, the figure paths' `YYYY-MM`) instead of adding a production clock seam for one test.
- The design doc's failure stage for a scratch persist failure is unnamed; I chose `publish-failed` (nothing was published).
- The refusal returns a `Failed` result and closes the receipts row: the "no write" in the site table is read as no filesystem write (vault, staging, scratch root). The receipts row already exists from intake and must reach a terminal state.
- Existing tests edited only to add the new argument: `figures/tests.rs` (3 `store` calls) and `publish/tests.rs` + `tests/x.rs` (one `UrlPublish` literal each) gained `&PublishPolicy::Vault`. No assertion changed.
- Sidecar row (`root/system/intake/`): the pipeline writes no sidecar; it is intake's write (`record_received_with_sidecar`), wired for distill by `record_scratch_with_sidecar` in Phases 4-5. Nothing to do here.
- Receipts `scratch` column row: Phase 4, not done here.
### Tradeoffs
- Post-distill existence check vs. making each distiller's persist return an error under `Scratch`: one check covers every URL kind and leaves the shared distiller signatures and the ingest path alone; the cost is that the failure is detected by effect, not at the failing call (the persist warning is still logged there).
- `UrlPublish.policy` + early return vs. an `Option<&SourceArchive>`: an optional archive would be a second signal for the same policy; the policy is the one signal and also gates both rkvr cleanups.
- Kept the `UrlPublish.vault_root` / `publish_slides(vault_root, ..)` names: the scratch root is laid out as a vault (vault-relative embeds resolve when it is opened as one), so the name still tells the truth; documented on the field. Renaming would churn every existing test literal.
- Tests drive the real `process_content` against the article stub (two figures, vision stubbed, real tesseract on solid-colour PNGs, which yields empty OCR and does not affect the note because vision text wins) rather than calling `publish_url_note` directly, so Stage 0 and the effective config are exercised.
- Mutation partners, each run and each observed FAILING: `writes_nothing` with the policy swapped to `Vault`, with `effective_config` not re-rooting staging, and with the scratch note dest sent to the inbox; `refuses_non_url` with the refusal disabled; `inflight_hit_fails` with the scratch key un-prefixed, and with the `Vault` key prefixed; `persist_failure_fails` with the guard disabled; `matches_ingest_note` with a scratch-only one-word body change.
### Open questions
- `force` still skips the inflight guard under `Scratch` (unchanged semantics). The Phase 5 route should pass `force = false` so a second concurrent distill is refused; worth confirming when the route lands.

## Phase 3: preserve frames and OCR every run
### Design decisions
- `WorkDirGuard` moved out of `handlers.rs` into a new `borg/src/pipeline/frames.rs` (with `frames/tests.rs`), beside the `runs.yml` code; `handlers.rs` was at 1407 lines against the 1500-line bloat lint. `WorkDirGuard::new(path, preserve_to: Option<PathBuf>)`; its `Drop` calls `retire_work_dir`: copy the tree to `preserve_to` (when set), then `remove_dir_all`.
- The destination comes from one place, `PublishPolicy::frames_dest()` (`borg/src/pipeline.rs`): `root/frames` under `Scratch`, `None` under `Vault`. `try_extract_slides` (now taking `policy`) builds the guard from it, and `record_runs` is `preserve_to.is_some()`, so runs.yml is written exactly when the work dir will be preserved.
- The guard is the single exit for every path. `keep()` is gone: on the slide-note path the guard itself travels in `SlidePayload.slides_source_root` (now a `WorkDirGuard`, `AsRef<Path>`), and `process_url_inner` calls `payload.slides_source_root.retire()` (a consuming no-op whose drop preserves and removes) where it used to `remove_dir_all` (the old `pipeline.rs:1032`). `slide_payload.as_ref()` became `slide_payload.take()` so the guard can be consumed there.
- `copy_tree` (`frames.rs`) copies regular files and directories only (symlinks and specials skipped, matching the Phase 5 file route's regular-files-only rule) and skips the source video by extension (`mp4`, `mkv`, `webm`, `m4a`, `part`). Copy, not rename, per the doc.
- `runs.yml`: `frames::run_records` builds one `RunRecord` per classified run (`start`, `end`, `best-frame` relative to the work dir so it resolves under the preserved `frames/`, `category`, `confidence`, `ocr`), OCR'ing every best frame in parallel (rayon, like `slides::ocr_slides`) with `ocr::ocr_extract` and `pipeline.ocr-timeout-secs`; `frames::write_runs` writes them as a top-level YAML list into the work dir, so the guard carries it to `root/frames/runs.yml`. Called in `classify_and_filter_slides` after `classify_slides`, before `segment_filtered`; the manifest and the note still come from the kept runs only. Filter off: `segment_with_pairs` path untouched, no runs.yml.
- A failed classification or OCR keeps its entry: the value is `null` and `classify-error` / `ocr-error` names why, so the entry count always equals the tally's `classified=` (acceptance criterion 5) and every entry has an `ocr` key.
### Deviations
- Preserved layout is the work dir copied verbatim: extracted frames land at `root/frames/frames/frame_NNNN.jpg` (plus `frames.yml`, `slides.yml`, `slides/slide-NNN.jpg`, `runs.yml` at `root/frames/`), not flat `frames/*.jpg` as the doc's layout sketch shows. Same content; keeping the work dir's own shape means `frames.yml`'s and `runs.yml`'s relative paths resolve without rewriting.
- The doc says "skipping the `.mp4`"; the copy skips every source-video and yt-dlp intermediate extension (`mp4 mkv webm m4a part`), since `try_extract_slides` already accepts an mkv/webm merge result. Same intent (the Non-Goals line: not the source video).
- Behavior change under `Vault` too, as a consequence of the guard now riding in `SlidePayload`: a slide-path work dir used to leak in /tmp on any return between `process_youtube` and the old `pipeline.rs:1032` removal (quality gate, persist guard, any `?`); the guard's drop now removes it on those paths. The note's bytes do not change.
- `frames_work_dir_is_removed_on_every_early_return` (`borg/src/pipeline/tests.rs`): its second half pinned `keep()` ("a kept dir is the slide publisher's to remove"), which no longer exists; it now asserts `retire()` removes the dir the same way drop does.
- Test seam: `classify_slides` fans out on a `JoinSet`, and the test-only `ocr::bases` task-local does not cross `spawn`, so in tests every slide classification failed "outside scope". Added `ocr::carry_vision_base` (test: `ocr::bases::carry`, re-enters the caller's scope on the spawned task; production: identity) and wrapped the spawn in `slides/classify.rs`. No production behavior change.
- Slide-error test: "the stub fails the slide path after frame extraction" is induced by keeping every run (`architecture-diagram`) with a fabric binary that does not exist, so `fabric::run_pattern` errors after frames, classification and materialization.
- One extra test beyond the doc's two: `distill_policy_keeps_frames_on_slide_note` (slides pattern answers, note embeds a slide), because the success-path `retire()` in `process_url_inner` is a separate site from the handler's drop.
- The test helper `run_frames` boxes the `process_content` future: held inline under three task-local scopes it overflowed the test thread's stack (observed, SIGABRT).
### Tradeoffs
- Guard owned by `SlidePayload` vs. keeping `keep()` and computing the preserve destination again in `process_url_inner`: one owner and one destination computation, and drop covers every early return. `AsRef<Path>` on the guard let the existing `gemini_engine_slides_on_spawns_only_the_mp4_download` test (which `remove_dir_all`s `payload.slides_source_root`) pass unedited.
- A failed preserve copy or runs.yml write is a WARN, and the run continues (and the work dir is still removed): failing the slide path would change the note (fall back to text-only), and leaving the dir is the /tmp leak the guard exists to stop. The cost: a distill can succeed with an incomplete `frames/`.
- Real tesseract in the pipeline tests (on the stub's `testsrc` frames) vs. an injected OCR fn through `try_extract_slides`: tesseract is already a test requirement (article tests); `run_records` takes the OCR fn as a parameter and its unit tests cover the error mapping with a fake.
- Mutation partners, each run and each observed FAILING: `frames_dest` returning `None` for `Scratch` (all three new pipeline tests); the scratch run swapped to `Vault` (all three); `record_runs = false` (all three, at runs.yml); `process_url_inner` removing the dir before `retire()` (`slide_note` fails, the other two pass, as expected: they exit in the handler); `SOURCE_MEDIA_EXTENSIONS` empty (all three, on the mp4 check); the guard's `remove_dir_all` removed (all three, on the work-dir-gone check). The `Vault` half of the text-only test cannot be made to fail by a mutation (a `Vault` run has no scratch root to write to); it pins the absence.
### Open questions
- A preserve copy failure leaves a "succeeded" distill with a partial `frames/` and only a WARN in the log. If that should fail the run instead, it needs a signal out of `Drop` (e.g. an explicit fallible `retire` on every path); worth deciding before Phase 5 serves the tree.

## Phase 4: receipts `scratch` column and reader handling
### Design decisions
- v8 migration (`borg/src/receipts.rs::run_migrations`): `has_column`-guarded `ALTER TABLE receipts ADD COLUMN scratch INTEGER NOT NULL DEFAULT 0`, placed after the v3 rebuild like v4-v6; `SCHEMA_VERSION` is 8. The baseline `schema.sql` carries the column too, so a fresh DB needs no migration.
- The flag rides the INSERT that creates the row: `record_received_row` gained a `scratch` argument, and the public `receipts::record_received_scratch` is the only caller that passes `true`. `intake::record_scratch_with_sidecar(_config, root, ...)` calls the private `record_received_with_sidecar_to` (new `scratch: bool` parameter) with `root`, so the sidecar is `root/system/intake/<trace>.txt` and the vault is never touched.
- `Receipt` gained `scratch: bool`, read by `get` and `query` (SELECTs extended). `eval::remediate::plan` already reads each scored trace through `receipts::get(...).filter(..)`, so the exclusion is `status == "succeeded" && !r.scratch`; a scratch trace reads as `no_receipt`.
- The five excluded readers filter in SQL with `scratch = 0`: `eval/backlog.rs::succeeded_traces`, `receipts::{count_by_status, count_failed_by_stage, count_failed_since, count_crashed_since, count_degraded_since}` (everything `triage::audit_health_stats` calls; `triage.rs` itself needed no edit), oracle `failure_history`, and `backfill.rs`.
- `replay_one` calls `refuse_scratch(trace_id)` first, before the staging checks and any POST: it opens the receipts DB and bails `replay: trace <id> is a scratch distill run ...`. Fail loudly: a receipts DB that cannot be opened is an error, not a skipped check.
- Test seams: `backfill::received_at_map_from(conn, tz)` (the connection-injectable core of `load_received_at_map`) and oracle `OracleMcpServer::failure_history_at(path, req)` (the path-injectable core of the tool), both so a test can seed a DB without mutating `XDG_DATA_HOME`. New receipts tests live in a sibling `borg/src/receipts/scratch.rs` because `receipts/tests.rs` is at 1426 of 1500 lines.
### Deviations
- Reader inventory re-verified with `rg "FROM receipts"`: every cited reader exists and nothing was missed. Line numbers drifted only by this phase's own edits. `eval::remediate::plan`'s filter is on the `receipts::get` result, not a SQL clause; same effect, correct seam. `count_kind_since`, `list_stale`, `receipts::get`, `queue.rs`, `cortex/proposals.rs`, `eval/weekly/remediated.rs` are untouched, as the table says.
- `record_scratch_with_sidecar` takes the doc's `config` argument but does not use it (named `_config`): unlike `record_replay_with_sidecar` it needs no vault root. Kept so the Phase 5 route is written against the doc's signature; drop it then if the route has no use for it.
- `stages/raw/tests.rs::gate_0_rejection_is_recoverable_by_replay` now runs `replay::run` inside `with_xdg`: replay opens the receipts DB, and the test (outside any XDG sandbox) tripped the sandbox assertion. No assertion changed.
- `sb borg log` is untouched (included per the table); `Receipt.scratch` is available to it but not printed. No CLI flag added (Phase 5/6).
### Tradeoffs
- SQL `scratch = 0` in each reader vs. a shared `ingest_receipts` view: five one-line filters, each beside its own query, vs. a new schema object every reader and the oracle read-only connection would have to know; a view would also hide the filter from a grep for `scratch`.
- `refuse_scratch` opens the DB on every `replay_one` vs. checking only on some path: it is the one chokepoint before any POST, and replays are operator-paced, so the extra open is cheap.
- Mutation partners, each run and each observed FAILING with the filter removed: backlog (`AND scratch = 0`), remediate (`&& !r.scratch`), each of the five health counters in `receipts.rs` (all trip `health_counters_exclude_scratch_rows` and `audit_health_stats_conn_ignores_scratch_rows`), oracle `failure_history`, backfill, the INSERT flag (`record_received_scratch` passing `false`), and `refuse_scratch` neutralised (the control ingest trace in the same test records exactly one `POST /ingest`, so the zero for the scratch trace is the refusal's doing). Deleting the `refuse_scratch` call outright does not compile (dead-code error), so that check neutralised its condition instead.
### Open questions
- Oracle's `failure_history` opens `receipts.db` read-only and its query now names `scratch`. Oracle run against a DB the borg daemon has not yet migrated to v8 returns `no such column: scratch` (loud, not silent). Deploy order is `otto deploy` (borg daemon restart migrates), then oracle. Confirm that is acceptable, or say if oracle should tolerate a pre-v8 DB.

## Phase 5: daemon routes, feature flag, polling, retention
### Design decisions
- `POST /distill` (`borg/src/routes.rs::distill`): trace from `trace::generate(Cli)`, root `scratch::run_root(borg_distill_dir(), trace)`, `intake::record_scratch_with_sidecar` synchronously before dispatch (a failed write is `Failed` to the caller, as on `/ingest`), then a detached `tokio::spawn` of `pipeline::process_content` with `PublishPolicy::Scratch { root }`, `method = cli`, no tags, no note, `force = false` (so a second concurrent distill of the URL hits the inflight guard, closing the Phase 2 open question). Answers `Queued { trace_id }` like `/ingest`.
- The route calls `process_content` directly, not `dispatch::dispatch_ingest`: dispatch hardcodes `PublishPolicy::Vault`, and `cli` pings nobody, so its notification boilerplate would be dead code here.
- `record_scratch_with_sidecar` lost its unused `_config` parameter (Phase 4 open question): nothing about a scratch capture depends on the config.
- New module `borg/src/scratch.rs` (+`scratch/tests.rs`) owns the scratch tree: `DistillRequest`, `DistillManifest` (kebab-case keys, as the doc's manifest sketch), `ManifestFile`, `run_root` (a trace id must be one plain path component or it names no root), `requested_path` (`..` -> `PathRefusal::ParentDir`, root/prefix -> `PathRefusal::Absolute`, `.` dropped; no filesystem call), and `regular_files` (fresh `symlink_metadata` walk, regular files only, symlinks to files or dirs and special files skipped and never followed, sorted, missing root = empty list). Named `scratch`, not `distill`, because `stages::distill` and `config.distill` are Stage 2.
- `GET /distill/{trace}` and `GET /distill/{trace}/file/{*path}` share `routes::terminal_scratch_run`: 404 for a bad trace component, an unknown trace, or `scratch = 0`; 409 while `received`; 500 on a receipts error. The file route checks the path (400) before anything else, so a `..` request never touches receipts or the tree; then the shared refusals; then serves only a path the walk lists, streamed (`tokio_util::io::ReaderStream`), `application/octet-stream`. Error bodies are `{"error": ...}` JSON like `/queue`. All three sit in the `require_auth` subrouter (`server.rs::build_router`).
- `health::FEATURE_DISTILL = "distill"` added to `DAEMON_FEATURES`.
- `replay::PollOutcome { Terminal(IngestResult), CeilingReached }` is what `poll_trace_terminal` returns. Both callers (`replay::reingest_via_daemon`, `client::reingest_one`) map `CeilingReached` through one helper, `replay::ceiling_failure`, which produces the exact `Failed` reason both printed before ("trace did not reach a terminal state within the polling ceiling"). `reingest_one` still keeps its `Queued` result on a poll `Err`, as before.
- `retention::sweep_distill(root, retention_days, dry_run)` + `run_distill_sweep(config, root)`: one pass at startup then daily, gated only on `staging.retention_days` (0 returns at once, keeps everything), sibling task spawned in `serve_init` beside `run_sidecar_sweep`. Real directories only; a top-level symlink is neither counted nor removed. `sb borg retention sweep` sweeps the distill tree after staging (skipped by `--sidecars-only`, like staging) and prints a "Distill sweep disabled" line at 0.
- `borg/AGENTS.md` module map gained the `scratch.rs` entry because the `agents-map` CI lint requires every module documented; the distill narrative is left for the docs phase.
### Deviations
- `run_distill_sweep` takes the root as a parameter (the daemon passes `vault::paths::borg_distill_dir()`), not just the config: same effect, and a test can sweep a tempdir without redirecting `XDG_DATA_HOME`.
- `scratch_capture_flags_the_row_and_writes_the_sidecar_under_the_scratch_root` (`intake/tests.rs`) dropped its config/vault setup and its "nothing lands in the vault" assertion along with the parameter: with no config the function cannot know a vault, so that assertion could no longer fail.
- A finished scratch run whose tree is gone (swept) answers 200 with `files: []`, not 404: the doc lists only "unknown or `scratch = 0`" as 404, and the receipts row still exists.
- An extra 404 beyond the doc: a `{trace}` that is not one plain path component (`%2E%2E`) is refused before receipts, so no trace id can resolve outside the distill dir.
- `poll_trace_terminal`'s ceiling cannot be driven by a test in reasonable time (`hard_timeout_secs + 90` on a std `Instant`); its mapping is pinned by `ceiling_failure_keeps_the_reason_replay_and_reingest_print`, and `trace_polling_reports_a_terminal_trace_as_terminal` pins that a failed trace is `Terminal`, not the ceiling.
### Tradeoffs
- The POST test proves the `Scratch` spawn by its effect, not a seam: an unreadable blocklist (a directory at `blocked-domains.yml`) makes Stage 0 reject right after it stages the envelope, so the run ends with no network fetch, and the envelope must be under `distill/<trace>/stages/<trace>/` and not under the shared `staging.root`. The alternative, a spawn-injection seam in the route, would test the seam rather than the route.
- Sync receipts lookup and tree walk inside the async handlers, matching `trace_state`, vs. `spawn_blocking`: a scratch tree is one run's files, and the receipts sandbox is thread-local in tests.
- Mutation partners, each run and each observed FAILING: distill routes moved outside the auth layer (401 test); `ParentDir` ignored and root/prefix ignored in `requested_path` (400 test, each separately); `metadata` instead of `symlink_metadata` in the walk (symlink test); the `scratch` flag ignored (`scratch = 0` 404 test); `received` treated as terminal (409 test); `PublishPolicy::Vault` in the spawn (POST test; with staging off under Vault the run never reaches terminal and the envelope never appears); `record_received_with_sidecar` instead of the scratch capture (POST test, scratch flag); the task gated on `intake.retention-days` (both task tests); the sweep never deleting and deleting everything (old/young test, each); `enabled` forced true at 0 (zero-window test); a failed `/trace` mapped to `CeilingReached` (terminal poll test); `FEATURE_DISTILL` dropped from `DAEMON_FEATURES` (health test).
### Open questions
- Phase 3's best-effort frames preserve is now served as-is: a distill whose preserve copy failed is `succeeded` with a partial `frames/` and a WARN only. Unchanged here, as instructed; still queued for the implementation audit.

## Phase 6: `sb borg distill` client
### Design decisions
- The client is `borg/src/client/distill.rs` (+`distill/tests.rs`), a submodule of `client.rs` (which stays at its size), re-exported as `borg::distill` / `borg::DistillRun`. Libraries return typed data and only `sb` prints or picks exit codes: `distill` returns `Ok(DistillRun { dir, trace_id, note, failure })` and `Err` for everything that is exit 1; `sb/src/cli/borg.rs` prints DIR and the note path, and maps `failure: Some` to `ExitWith(3)`. Clap's exit 2 is clap's own.
- Order inside `distill_within`: explicit non-empty DIR refused (zero requests, even `/health`) -> `GET /health` refuses a daemon without `distill` (the `DaemonPoster::connect` shape, `FEATURE_DISTILL` from `health`) -> `POST /distill` -> default DIR `./<trace>` checked non-empty -> poll -> manifest -> every manifest path checked -> per-file download. Every error after the POST is wrapped with `distill trace <id> did not finish; its files stay on the daemon`, so stderr names the trace id (eyre prints the chain).
- Manifest paths are checked for ALL files before the first write (and before `DIR` is created): `checked_destination` reuses Phase 5's `scratch::requested_path` (`..` / absolute refused), refuses an empty result, then asserts the joined path `starts_with(DIR)`. A hostile listing therefore writes nothing at all, not a prefix of it.
- Downloads pass `hotkey.download-timeout` through `DaemonClient::get`'s per-call override; each segment of the path is percent-encoded (`urlencoding`, already a borg dep), because `DaemonClient::url` builds the URL by string format and a file named `a#b?.jpg` would otherwise be cut at the fragment. A body whose length differs from the manifest `size` is a download error (a truncated file never reads as success).
- `vault::daemon::HotkeyConfig.download_timeout` (humantime key `download-timeout`, default `300s`, `DEFAULT_DOWNLOAD_TIMEOUT`) sits beside `request-timeout` with the same deserializer shape, so a bad value names the key. `config/templates/borg.yml.example` documents it in the hotkey block.
- `replay::poll_trace_terminal` now delegates to `poll_trace_terminal_within(daemon, trace, ceiling, interval)`; `polling_ceiling(config)` and `poll_interval()` hold the defaults (`hard_timeout_secs + 90`, 2s). That is the injectable ceiling: the never-terminal test runs with an 80ms ceiling and 10ms interval and sleeps for neither the real ceiling nor interval.
- The success note path is the manifest's single top-level `*.md`, joined onto DIR; if none, only DIR is printed.
- `borg/src/stub.rs` gained `Behavior::Distill(DistillStub)`, a routed stub (`/health`, `POST /distill`, `GET /trace/{id}`, `GET /distill/{id}`, `GET /distill/{id}/file/..`) that serves a real tempdir tree through `scratch::regular_files`; its reply type became bytes so a file body is served as-is.
### Deviations
- The doc says the client lives in `borg/src/client.rs`; it is `borg/src/client/distill.rs` under it. Same effect; `client.rs` plus a 250-line client and its stub-heavy tests would have blurred the existing file.
- Default-DIR non-empty check sits before the poll (right after the POST returns the trace id), not "after POST, before download" at the last moment: same guarantee (after the POST, before any download), but a refused default DIR is reported before waiting out a pipeline run.
- The default-DIR test seeds `./cl-distill-stub/` in the test cwd (the `borg` crate dir) and removes it before asserting; changing the process cwd would race sibling tests. The dir name is unique to that test.
- `sb borg distill` has two clap tests (parse; missing URL is exit 2) but the exit-code mapping 0/1/3 itself is not unit-tested at the `sb` layer: `BorgCli::run` loads real config, and the mapping is four lines. The 0/1/3 split is pinned at the library boundary (`Ok` / `Err` / `Ok` with `failure`).
- The annotated config example is `config/templates/borg.yml.example`; the repo ships no other annotated hotkey example.
### Tradeoffs
- Validate-all-then-write vs. write-as-you-go with a per-file check: a bad entry late in a long listing would otherwise leave a partial DIR the operator must clean; validating first costs one pass over a list already in memory.
- Whole-file `bytes()` per download vs. streaming to disk: matches `DaemonClient`'s existing buffered style and lets the size check run before the write; a frames tree is many modest JPEGs, not one huge file.
- A new routed `Behavior::Distill` vs. a generic closure behavior: the closure form would put route logic in every test; one purpose-built stub keeps the tests to "state + tree".
- Mutation partners, each run and each observed FAILING: feature check disabled (`a_daemon_without_the_distill_feature...`); explicit-DIR refusal removed (`a_non_empty_explicit_dir...`); `requested_path` replaced by a plain `PathBuf::from` (climb, absolute and `checked_destination` tests); `CeilingReached` mapped to success (`a_trace_that_never_terminates...`); failure reason dropped (`a_failed_trace_still_writes...`); default-DIR check removed (`a_non_empty_default_dir...`). A mutation that bypassed `checked_destination` entirely left it unused and did not compile (dead-code error), so the path-check mutation was done at `requested_path` instead.

# borg — Ingestion Library

> Read this before touching `borg/`. Deeper nodes: `src/pipeline/AGENTS.md` (orchestration), `src/stages/AGENTS.md` (staged artifacts), `clients/AGENTS.md` (browser/hotkey clients).

## Purpose

borg owns durable capture, multi-channel ingest, and the staged pipeline that publishes notes into the Obsidian vault. It does NOT own the vault schema or frontmatter contracts (delegated to `vault`), nor CLI orchestration (owned by `sb`). lib-only; consumed by `sb`.

## Entry Points

- `serve_init(config, version) -> (ServerStartup, ServerHandle)` (`server.rs`, re-exported as `borg::serve_init`) — bootstraps the HTTP listener (port 8181), watchdog, and the Telegram/Discord/ntfy/Signal transports (one `start_*` fn each in `server/transports.rs`, returning its `SubsystemStatus`).
- HTTP endpoints (`routes.rs`): `POST /ingest` (JSON), `POST /ingest/file` (multipart), `POST /note` (JSON), `GET /trace/{trace_id}` (`routes.rs`, a receipts row's terminal state plus `source-durable` (the trace's source archive exists on this host) — replay/reingest poll this because the receipts DB is per-host), `GET /queue[?batch=<id>]` (ingest-queue snapshot via `queue::load` in `spawn_blocking`; unknown batch 404, DB error 500, never idle), `GET /channels/search?handle=@x&q=...&limit=N` (`youtube::search_channel`: one `yt-dlp --flat-playlist -J` call bounded at 8 s, `watch?v=` hits only; bad handle/query/limit 400 before yt-dlp runs, yt-dlp failure/timeout/unparseable output 502 with `vault::channel::ChannelSearchFailure` carrying the stderr tail), `GET /health`, `GET /health/audit`. `/ingest`, `/ingest/file`, `/note`, `/trace/{trace_id}`, `/queue`, and `/channels/search` sit behind `routes::require_auth` (`routes.rs:49`), wired as a `route_layer` over that subrouter in `build_router` (`server.rs:40`); `/health` and `/health/audit` stay open for probes/dashboard.
- CLI helpers (`client.rs`, re-exported at the crate root): `note(config, text, tags)`, `ingest_file(config, file_path, tags, force)` (in-process pipeline), `ingest(...)`, `reingest(...)` (through the daemon's `/ingest`) → `IngestOutcome` / `ReingestReport`.
- Pipeline dispatch: `pipeline::process_content(content, tags, method, force, config, trace_id) -> IngestResult`.

## Contracts & Invariants

1. **Durable capture at the door, before dispatch.** Every door calls `intake::record_received_with_sidecar()` synchronously before any classify/pipeline work — writes the raw-input sidecar + receipts `received` row. Both must succeed or the caller returns `Failed`. No accepted input is ever silently dropped.
2. **Receipts DB is the sole durable failure store.** Outcomes (success/duplicate/failure) are written at the pipeline's terminal chokepoint (`record_terminal_to_receipts`). State machine: `received → succeeded | failed(stage) | crashed`. A `succeeded` row also carries a `degraded` flag: the note landed but via a distill fallback (e.g. a fabric API error), so its body is impoverished. Because degraded notes read as `succeeded`, they hide in the status counts — `audit_health_stats` exposes `degraded_24h` (alongside `failed_24h`/`crashed_24h`) as the silent-quality signal, queryable via `count_degraded_since`/`sb borg log --degraded` and Warned by `sb doctor`. Legacy markdown intake/DLQ tables were excised.
3. **Notifications are detached from the HTTP response.** Sinks fire inside `tokio::spawn` off the response path (`routes.rs`); the response returns in milliseconds and survives client cancellation.
4. **Test notifications are disabled** when `notify::real_notifications_disabled()` is true (tripped by `cfg!(test)`, nextest, `CARGO_TARGET_TMPDIR`, or `BORG_DISABLE_NOTIFICATIONS`). No test path leaks a real toast/message.
5. **`IngestRequest` is additive-only** (`types.rs`). Required: `url`. Optional: `tags`, `priority`, `force`, `method`, `note`, `replay-of`, `replay-origin`. `replay-of`/`replay-origin` (`ReplayOrigin::AutoRemediation`) are written onto the receipts row by the INSERT that creates it (`intake::record_replay_with_sidecar` -> `receipts::record_received_with_lineage`), never by a later UPDATE; `replay-origin` without `replay-of` is refused before intake. `/health` lists `features: ["replay-of"]` (`health::DAEMON_FEATURES`) so a client can refuse an older daemon that would drop the fields. An auto-remediation never pings the operator (`dispatch::pings_operator`). Never remove/rename a field — clients (extension, bookmarklet, hotkey) depend on it; a required-field addition needs a coordinated extension re-sign in the same PR.
6. **Signal privacy gate is load-bearing** (`signal.rs::accepted_envelope`): accepts only Note-to-Self sync and allowlisted-peer DMs, behind a fail-closed rate gate.
7. **Audit duplicate detection is content-hash, never `source:`-string** (`audit.rs`). `build_dup_index` groups notes by the SHA-256 of their normalized body; the `source:` field does NOT decide duplication (a shared batch label like `pais-migration` must never collapse distinct notes). Empty/short bodies (< `MIN_DUP_BODY_LEN`) never group. Body-identity is authority to REPORT only: `--fix duplicate` and blanket `--fix` move nothing. Destructive quarantine is the explicit `--fix duplicate-quarantine` opt-in, gated by `quarantine_eligible` (identical normalized bodies AND a shared non-empty `source:`), keeping the lexicographically-first note. See `docs/design/2026-06-19-content-hash-dedup.md`.
8. **Ingest-queue snapshot is computed once, on the daemon, and fails closed** (`queue.rs`, `GET /queue`; design: `docs/design/2026-10-04-ingest-queue-status.md`). `queue::snapshot` is the single place batches and the queued | processing | wedged | succeeded | failed partition are decided; `sb borg queue`, `sb borg wait` and oracle `ingest_queue` only render or poll it. `receipts.started_at` is stamped once, at the general permit grant, inside `renew_lease`; a queued row ages from `received_at` so a missed stamp still reaches `wedged`. Harvest (`method=harvest`) and `rejected` rows never join a batch. A DB or parse error is a 500 (or a `load` error), never `idle`; the `health_audit` `unwrap_or_default()` is the pattern NOT to copy. Config: the `queue:` block (`wedged-after`, `batch-gap`, humantime strings typed at deserialize).

9. **One YouTube fetch per ingest, through the engine seam** (`youtube/engine.rs`; design: `docs/design/2026-10-16-youtube-gemini-engine.md`). `pipeline::process_youtube` calls `fetch_video` once; it runs `youtube::engine::fetch(config.youtube.engine, ..)` and returns a `VideoFetch { metadata, transcript, segments, engine, fell_back }` that the slides path (`try_extract_slides` binds `segments`) and `distill_for_publish_video` both consume; neither re-fetches metadata or captions. Fallback: `FetchError::is_permanent()` (`NotFound`, `NotLive`) fails `fetch-failed` with no fallback; any other error runs `youtube.fallback` when set and marks the receipt `degraded` (`receipt_degraded`, beside `tags_degraded`). The `yt-dlp` arm is the original metadata + fabric `-y` -> subtitles -> Groq chain plus one raw-VTT fetch, and keeps the breaker exactly as before (`fetch_metadata` checks and records; subtitles, audio and the slides mp4 only check). The `gemini` arm (`dataapi.rs` + `gemini.rs`) never touches the breaker: breaker state is yt-dlp's. Every ingest-path yt-dlp process starts in `youtube::spawn::yt_dlp`; under `cfg(test)` it is a task-local counted stub (`spawn::scope`) and an unscoped spawn errors, so no test starts a real yt-dlp. The gemini arm's clients read stub base URLs from `engine::bases::scope` in tests and fail outside one. Config: `Config::validate` (run by every `sb borg` subcommand) checks only structure; the env-dependent gemini key check is `Config::validate_daemon_start`, called first in `serve_init`, because only the daemon has `borg.env`. The gemini budget bounds the Data API calls too (`engine::fetch_gemini`), each also capped by `youtube.data-api.timeout`.

## Patterns

- **Add an ingest source/channel:** write an async `run(config, ...)` that generates a trace (`trace::generate`), calls `intake::record_received_with_sidecar()`, then detaches to `pipeline::process_content()`; route results to `notify::*`. Mirror `telegram.rs` / `discord.rs` / `ntfy.rs` / `signal.rs`. New channels go side-by-side, not behind a trait.
- **Stage flow for a URL:** Stage 0 fetch → Stage 1 extract → Stage 2 summarize/distill → Stage 3 publish (vault + ledger + receipts). See `src/stages/AGENTS.md`.

## Anti-patterns

- Don't call `process_content` synchronously from an HTTP handler — it blocks the response and exposes the pipeline to cancellation.
- Don't write to ledger/receipts from inside `process_content`; use the terminal dual-write chokepoint so all outcomes are captured consistently.
- Don't inline the `real_notifications_disabled` check at call sites — call the sink unconditionally; the sink decides.

`eval::fabric_judges` refuses a blank model for a judged run and `EvalConfig::validate` a blank `eval.judge-models` entry); the `--inject` report also prints pairwise Cohen's kappa (`eval/agreement.rs`) between every rater with a current, error-free `baseline` row on the sampled originals (each judge model's two checks; rows the dropped DeepEval and MiniCheck tools left behind are not raters), at the trace level (flags the note) and the claim level (claim supported), with kappa undefined (`n/a`), never 1.0, when both raters gave every item one label; `eval.judge-models` defaults to `gemini-2.5-pro` (the default judge, also `--judge-model`'s default on a judged run) then `claude-sonnet-5` (the second judge); `--candidate-split N --pattern P` / `--candidate-pattern FILE --pattern P --traces ... [--holdout ... --write-candidate [DIR]]` / `--apply-candidate FILE` (`eval/candidate.rs`, `eval/candidate/file.rs`) score a proposed single-call distill pattern against the current one on staged traces that reach it: each arm is a re-distill with only that pattern swapped (`CandidateFabric`, every other pattern resolved as `--patterns-dir`), distills cached per pattern-text hash in `candidate_distills`, graded rows written as `candidate` rows (`run_id` = pattern + text hash); the metric is quote grounding x claim support x listicle survival, 0 when claims or enumeration items per note fall more than `eval.candidate.max-coverage-cut` (`objective`); `--write-candidate` re-scores on the disjoint holdout and writes `<pattern>-<date>.md` (frontmatter record, metrics, trust, diff) under `eval-reports/candidates`; `--apply-candidate` refuses while `judge-claims` under the candidate's judge is untrusted, when the repo pattern no longer hashes to the measured base, when a holdout trace is swept, or when a fresh holdout re-distill does not confirm the win, and only then writes `borg/patterns/<P>.md`; the GEPA search that proposes candidates is the `eval/` uv project (`otto gepa`); `--regenerate --format json` prints both arms' records (`run_id` `regenerate:without-note|with-note`) for `bin/promptfoo-check`; `--patterns-dir <DIR>` resolves every eval pattern (distill, judge, intent) from DIR, e.g. `borg/patterns`, through `eval::patterns::PatternDirFabric`, leaving live ingest's resolution untouched; `--remediate [--apply]` (`eval/remediate.rs`) lists every scored trace whose current, error-free required row fails (`row_failure`: the judge checks by `agreement::trace_flag`, the deterministic checks as the report reads them), gates each failure (deterministic always acts, a judge check only when `trust::judge_check_trust` says trusted; a blocked one is listed with judge, check and class), and with `--apply` claims one attempt per source URL in a `BEGIN IMMEDIATE` transaction on the receipts DB (`remediations` table plus `replay_origin='auto-remediation'` intake rows; claim inserted only at count 0 with a copy of the trigger row's `metrics_json` in `trigger_metrics_json`, the weekly report's frozen "before", released only when the POST provably never reached intake) before POSTing `/ingest` with the original method, `force`, `replay-of` and `replay-origin: auto-remediation`; `DaemonPoster::connect` refuses a daemon whose `/health` lacks `replay-of`; `fixtures::probe_staged_trace` is the single-trace staged reader that tells a swept trace (`Absent`) from an unreadable one (`Unreadable(why)`), the source read path of `sb oracle eval --target answerability`).
